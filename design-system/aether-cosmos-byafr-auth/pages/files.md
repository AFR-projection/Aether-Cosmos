# Files Browser Override — Aether Cosmos ByAFR

Use the global vault palette, but tighten the rhythm to a working list: 8px inside a row's metadata, 12px between a row's controls, 16–20px between the toolbar, the folder section and the file section, and 20px only below the page heading block. The browser is consulted dozens of times a day, so it should feel dense and quiet rather than spacious and impressive.

Keep one focal point per screen: the heading block — icon tile, real folder name, and the count line beneath it. Everything else is chrome. The toolbar carries search, view toggle, sort and create; it must never grow a second row of primary buttons or repeat an action already reachable from a row's own menu. Accent tone belongs to exactly one control at a time (the create button, or the active filter pill, or the active sort choice) and to nothing else; role badges use `warning`/`success`, error toasts use `danger`, and no component may carry a raw hex value.

The heading must always resolve to something an assistive technology can read. A deep link into `/files?folder=<id>` carries only an id, so the name comes from the cached folder-path query the breadcrumb already reads; while that request is in flight, show a skeleton bar with an `sr-only` label rather than the literal word "Folder". A shared tree suppresses the "My Files" root link and routes every crumb to `/shared-with-me/<id>`, because the owner's route would leave a member on an empty page, and the trimmed ancestor names would map out a tree they were never granted.

The list header stays sticky under the mobile chrome (`top-[calc(3.5rem+var(--safe-top))]`, `lg:top-0`) so column meaning and select-all survive a long scroll. No ancestor of that header may set `overflow`, or the sticky position silently dies; the rounded clip belongs on the virtualized rows container only. Both views are window-virtualized with their own instance, so a 200px grid measurement never leaks into a 56px list row, and both re-measure their scroll margin when folders or filter chips appear above them.

Every empty state must name its own cause — trash, no search results, an active type filter, or a genuinely empty folder — carry an icon and a text explanation, and offer the one action that resolves it (reset filters, or upload). A viewer without edit rights gets the explanation without the action rather than a button that will fail. When folders are present, the file section's empty state collapses to a single dashed line so it never outweighs the content above it.

Motion is limited to menu entrance, selection feedback, and skeleton pulse; it explains state changes and nothing more, and it yields to the user's reduced-motion preference. Selection, sort direction, and filter state must each be legible without color: a tick for the current sort, `aria-pressed` on filter pills, `aria-checked` on the select-all control, and a count in the toolbar.
